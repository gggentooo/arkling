# ArkLing Technical Document

## Purpose

ArkLing is a Svelte 5 single-page reader for Arknights story scripts. It presents aligned target-language and system-language dialogue, supports focused and side-by-side reading modes, and can render Mandarin pinyin or Japanese furigana/romaji annotations.

## Runtime structure

- `src/main.ts` mounts the Svelte application and imports the global stylesheet.
- `src/App.svelte` provides the top-level layout and composes `TopBar` and `MainArea`.
- `src/app.css` contains all global, layout, component, responsive, typography, and annotation styles.
- `src/components/TopBar.svelte` renders language, mode, and annotation controls. Annotation changes preserve the first visible line's viewport position while asynchronous markup is generated.
- `src/components/MainArea.svelte` renders the story selector at the top and bottom of the reading area, loading state, active reading view, scroll-to-top control, and footer. The second selector is intentional: it keeps episode navigation available after the reader reaches the end of a long script.
- `src/components/StorySelector.svelte` renders category, chapter, episode, navigation, and skip-to-line controls.
- `src/components/SideBySideView.svelte` renders each line in target and system panes.
- `src/components/FocusedView.svelte` renders target lines with optional revealed system translations.
- `src/components/LineItem.svelte` is the reusable line renderer. It selects raw or annotated text and supports interactive reveal behavior.

## State and data flow

`src/lib/state/learningState.svelte.ts` owns language selection, learning mode, annotation settings, loaded script lines, and revealed focused-mode lines. `src/lib/state/storySelectorState.svelte.ts` owns category/chapter/episode selection, loading state, and story metadata. Both managers use Svelte 5 runes (`$state` and `$derived`) and are exported as shared singleton instances.

At startup, `StorySelector` loads the story review table, restores valid URL query indexes, and loads the selected episode. A story load fetches target and system raw scripts, parses them, aligns them by position, stores the resulting `ScriptLine[]`, and applies the active annotation settings. Selector changes repeat the same load path. The URL is updated with `cat`, `chap`, and `ep` indexes after restored state is valid.

`MainArea` renders `StorySelector` twice by design. The bottom instance is a convenience control for changing stories without scrolling back to the top; it is not redundant markup to remove during cleanup.

Annotation toggles update state, generate cached markup asynchronously, and replace only the latest request's result. The toggle handler waits for the annotation operation and Svelte's DOM flush before adjusting `window.scrollBy`, keeping the same visible line in place when ruby/pinyin markup changes line height.

## External services

`src/lib/api/arknights.ts` fetches public raw JSON and text files from GitHub repositories:

- Chinese: `Kengxxiao/ArknightsGameData` (`zh_CN`)
- English: `ArknightsAssets/ArknightsGamedata` (`en`)
- Japanese: `ArknightsAssets/ArknightsGamedata` (`jp`)
- Korean: `ArknightsAssets/ArknightsGamedata` (`kr`)

The app requests `gamedata/excel/story_review_table.json` and `gamedata/story/<story path>.txt`. Story tables are cached in memory and `sessionStorage`; scripts are cached in memory. Japanese annotation initialization uses a local `dict/` asset path and falls back to the Kuromoji dictionary CDN if the local dictionary is unavailable. Google Fonts are imported by `src/app.css`.

## Parsing and annotation loop

1. Fetch raw story text for the selected languages.
2. `parseArknightsScript` removes unsupported directives/tags and converts dialogue, decisions, subtitles, and plain lines into parsed entries.
3. `alignScripts` combines entries into `ScriptLine` objects with stable `line-N` IDs.
4. `LineItem` chooses the target text or `annotatedText` based on current settings and renders trusted generated markup with `{@html ...}`.
5. Pinyin is generated by `pinyin-pro`; Japanese annotations are generated by Kuroshiro/Kuromoji. Both use in-memory caches.

## Build and verification

- `npm install` installs dependencies.
- `npm run dev` starts the Vite development server.
- `npm run check` runs `svelte-check` and the TypeScript compiler.
- `npm run build` creates the production bundle.
- `npm run preview` serves the production bundle locally.
